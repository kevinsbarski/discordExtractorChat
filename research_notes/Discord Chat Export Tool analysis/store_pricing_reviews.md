## 3. How licensing is implemented technically, and telemetry

### Takeaway
Licensing has four parts:
- **Identity:** Supabase Auth (project `zjtlssppxzesxvhwokje`), using Google OAuth via `chrome.identity.launchWebAuthFlow` with PKCE. This is the only use of the `identity` permission.
- **Entitlement:** a third-party-style licensing API at `worker-api.extbolt.com` (project `61a31dd7-…`) answers `{isPro, isReviewed, expiry_date}` and serves the Paddle plan config.
- **Storage:** results are cached in `chrome.storage.local` (`isPaid`, `expiry_date`, `userData`, …).
- **Enforcement:** the 100/200 message limit is checked only in the client UI, and the "5-star" reward is granted locally the moment the user clicks, without any verification.

Telemetry is minimal in 1.7.0: Sentry is bundled with no DSN (so it is inert), there are no analytics SDKs, and the uninstall URL points to a Google Form. Every open of the popup or export page still makes 3–4 calls to the ExtBolt API, which reveals usage timing and IP to the developer.
